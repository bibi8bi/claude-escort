# 护航系:护航 / 并驾 / 全力 / 任务树 / 长跑

一个文件五组口令,**是叠加关系不是并列关系**:后一层默认包含前一层。

| 你说 | 等于什么 | 读哪几节 |
|---|---|---|
| 护航 <活> / 全程护航 | 五步闭环,中间不问,只在必停点停 | 甲 + 乙 |
| 并驾 <活> / 进阶并驾 <活> | 护航,但第 3 步「干」换成批量并行,并叠加降耗纪律 | 甲 + 乙 + 同目录 `convoy.md` 全文 |

| 任务树 / 出任务树 | 渲染 task_plan 进度树 | 丁 |
| 护航 长跑 <活> / 并驾 长跑 <活> | 叠在护航或并驾上:到线不换窗口,先收尾、再让 Claude Code 自动压缩、压完接着干 | 原来那几节 + 戊 |

# 甲、护航:五步闭环 + 必停点

用户说「护航 <活>」= **一次性授权依次跑完下面五步,不用再逐步问「要不要」**。
目的是用户不用盯着也不会偏航,所以**每一步的产物都要落在盘上**(task_plan 条目 / 验收报告原话或主会话的检查输出 / commit),不许只在对话里说过。

## 五步

1. **摸底**:看 `git log --oneline -10`、`git status` 和当前分支、progress 最新一条、task_plan,再跑一眼任务树(丁节)。git 痕迹、文档声称、运行输出三方**任一对不上就停**,列出差异问用户。
2. **登记**:同一目标的小修归到已有父任务,只记实际变化;独立的新活在 task_plan 里没有对应条目 = 支线,**当场登记**(父任务 / 为什么值得岔出去 / 什么算完)再动手。独立新活同时**落盘**一段 `隐式默认(N 项):`,格式见乙节「隐式默认记账」。
3. **干**:先列 Files 清单(要改哪些文件),再记基线(哪条命令 / 什么结果 / 哪个 commit 的输出),然后按项目纪律干(要 TDD 的仓照 TDD,不越界,不碰清单外的文件)。同一个模板要铺到 **≥3 个目标** = 批量活,先立标杆再复制,见乙节「批量活标杆」。**每道门都要写目的**:写下来的验收门、判据、测试题,同行或紧邻一行必须写「在验:<哪个目的>」;写不出来 = 这道门还没想清楚,不许开跑。
4. **验**:**按风险派验收官**。动了权限、共享数据、公共接口、迁移、对外交付完整性,或者逻辑主会话自己难自证 → 派,任务书给齐:①Files 清单 ②基线命令 + 结果 + 出处 ③验收命令(每条带「在验:」)④临时实例怎么起、用哪个端口、怎么清理 ⑤留给用户判断的事。低风险、可回退、结果一眼能判的小改 → 主会话自己针对性检查,把命令和输出写进 progress。首行 FAIL / BLOCKED → 自己修 → 重派,**最多 2 轮**(任何一道门都适用,不止验收官);2 轮不过按必停点停,不许自己判「应该没事」。
5. **收**:验完(派了验收官的要 PASS)写 planning(progress / task_plan)、commit、push,最后出一棵任务树当收尾视图。树头今日 0 提交、本会话也没动 task_plan,就明说「今天没挪」。

## 必停点(一律停下问用户,不许自作主张)

- 要**删既有测试或断言**(削弱断言换绿,同罪)
- 要动**真库 / 真钱 / 真发布**:真调付费接口、真上线、给客户推送、改生产数据
- 要**重启用户正在用的服务**:在用的进程跑的是旧代码,拿它做验收 = 假验收
- **同一道门连续 2 轮不过**:停下来第一件事不是再修一次,而是把那道门的「在验:」念一遍,回答两问:①这道门要验的目的,是不是已经用别的方式达成了?②是系统没过,还是这道门本身坏了?答完把报告原文交给用户
- 发现**需求或计划本身错了**(要改方向,不是改实现)
- 要**写别的仓**:只读,要改就写一份交接说明给那个仓的负责人
- **批量活的标杆含给人读的文字或视觉版式**(文案 / 标签 / 配色 / 版式):标杆先给用户过目定稿,再铺其余
- **第 2 步的隐式默认矩阵没覆盖的决策类型**:不许现造一个默认值糊过去
- 项目文件里标了「要用户亲验」的事项:只验技术前置,不代验、不代过
- **样品闸**(并驾默认开,见 `convoy.md` 第八小节),与本清单同权

## 汇报(护航跑完只给这三条,30 秒能读完)

1. 干了什么(一句话 + 动了哪几个文件)
2. 验收官首行**原话**(PASS / FAIL / BLOCKED),体验师同理;按风险没派的,写主会话跑了哪几条检查、结果如何
3. 还剩什么 / 卡在哪 / 要用户定什么

不铺垫、不复述过程、不报百分比。

## 可派的护航 agent

定义文件在本仓 `agents/` 目录,装到 `~/.claude/agents/` 后全机可用。

- **验收官**(`验收官.md`,只读):口径同第 4 步。报告第一行写死 PASS / FAIL / BLOCKED,每条结论三段:整行命令 / `exit=N` / 输出末 10 行原文。自带取证预算,到点必停写报告。派单时把下面这段原样抄进任务书开头:

  ```
  # 报告第一行:照下面这行原样写,把尖括号那处替换掉,前后都不许加别的字
  #   第一行 = `PASS` 或 `FAIL:<一句原因>` 或 `BLOCKED:<卡在哪>`,整行到此为止。
  ```
- **体验师**(`体验师.md`,两档):**档A·出稿前**只对新建 UI,手上只有稿(线框 / 交互稿 / 字段清单)时派,审操作直觉不审美观(第一眼点哪 / 有没有断头路 / 状态是不是只靠颜色区分 / 有没有生词);**档B·收尾后**,布局、交互、配色有变化才派,结论必须来自真截图,截不到图首行必须 BLOCKED。**档A 过了不能顶替档B。**

三条纪律:子 agent **永远不直接对用户说话**,报告一律回主会话处置;角色封顶 4 个,加新角色要用户拍板;项目里有术语表的,每份任务书开头写一行「开工前先读 <术语表路径>,专有叫法以表内定义为准」。
额度:子 agent 照算订阅用量,派多了烧得快。

# 乙、护航细则(五步里只留指针,细则住这儿)

## 隐式默认记账(第 2 步用)

护航 = 撂开手,代价是我替用户做了一串他从没说过的选择。独立新活第 2 步登记时必须**落盘**下面这段(写进 task_plan 那条目下,或本次 progress),不许只在对话里说过;归到已有父任务的小修沿用父任务那份,父任务没有才写:

```
隐式默认(N 项):
- 提交方式=<在当前分支直接 commit / 开分支 xxx> · 想改:<一句话>
- 落点=<哪个仓 哪个目录> · 想改:<一句话>
- 备份与测试=<不备份不加测试 / 先备份 / 照该仓 TDD 补测试> · 想改:<一句话>
- 推送=<push 到 origin / 无 remote 停下> · 想改:<一句话>
```

**可数自查**(交付前跑,任一不过 = 第 2 步没做完):
- `N` 必须等于紧跟其下的条目数:`grep -c '^- .*· 想改:'`
- 四类一个不许少:`grep -cE '^- (提交方式|落点|备份与测试|推送)='` 必须 ≥ 4,四个类名各至少命中一次
- 每条 `· 想改:` 后面不许空着:`grep -cE '^- .*· 想改:\s*$'` 必须是 0

**预设矩阵**(默认值只许从这里取):

| 决策类型 | 默认取值 |
|---|---|
| 提交方式 | 在当前分支直接 commit;项目规则写了「禁止在默认分支直接 commit」才开分支 |
| 落点 | 当前会话所在的仓;要写别的仓是必停点,不是默认值 |
| 备份与测试 | 不额外加测试;要动数据库先备份;该仓要求 TDD 就照 TDD |
| 推送 | push 到远程;没有 remote 就停在这步提示用户去配,不擅自建 |

矩阵没覆盖的决策类型 = **必停点**。

## 批量活标杆(第 3 步用)

**同一个模板 / 同一段结构要铺到 ≥3 个目标**才算批量(各写各的不算)。先把**条目数最多**的那一个做到定稿,定稿路径记进 task_plan 当标杆,再照它铺其余。**没有定稿模板之前不许并行铺**;定稿之后可以并行。

「条目数最多」的数法写死一条命令,把目标清单填进去原样跑,**输出第一行就是标杆**,不许另挑:
```
for f in <目标1> <目标2> <目标3>; do if [ -f "$f" ]; then printf '%s\t%s\t%s\n' "$(command grep -c '^## ' "$f")" "$(wc -l < "$f")" "$f"; else printf '0\t0\t%s\n' "$f"; fi; done | LC_ALL=C sort -k1,1nr -k2,2nr -k3,3
```
- 主键 = `^## ` 二级标题数(降序);并列比行数(降序);还并列按路径字节序取第一个。同一份清单谁跑都是同一个标杆。
- 目标全是新建(全出 `0 0`)时照样给出字节序第一个,在第 3 步写一句「目标全 0 条目,标杆按字节序取 `<路径>`」。

**铺完对盘,不靠人眼看**:每个复制件的 `^## ` 二级标题数必须与标杆相等,行数差 ≤ 标杆行数的 1/10。标杆**最多 2 轮**不定稿就停下交给用户。

**停不停只看一条:这份产物用户要不要逐字读。** 三问按顺序问,任一为「是」→ 停(标杆先给用户过目定稿);三问全「否」→ 不停,把标杆的验收命令写出来自己按它判。
1. **落点**:产物是 `task_plan.md` / `progress.md` / `README*` / `*.html` / `docs/**`,或任务书里点名「交给用户的报告」?
2. **任务书措辞**:出现「给用户过目 / 定稿 / 对外发 / 客户可见」任一字样?
3. **承诺性文字或视觉取值**:产物里 `grep -nE '承诺|保证|上线|对客户|对外发'` 有命中,或 `grep -nE '#[0-9a-fA-F]{6}|[0-9]+px'` 有命中?

脚本、命令输出、`exit` 码、日志、数据文件、代码里的提示串都**不算「给人读的文字」**。

每轮交标杆都列出「还能改的 3 项」:要停的那类列完等用户回,不用停的那类默认采纳第 1 项继续。

## 报告复算(第 4 步用)

**归主会话跑**(让验收官自己数自己 = 钥匙又回到被审方手里)。每收到一份验收官报告、汇报给用户之前都要跑,首行 PASS 的也一样:
1. **落盘**:报告原文写进 `<scratchpad>/验收官报告-第N轮.txt`。
2. **复算**:报告里每处 `[判据: <命令> → <期望输出>]`,把命令**原样复跑**,期望串必须与实得输出的某一整行完全相等。
3. **判**:有一处对不上 = 这份报告不合格。先分锅:**缺证据、基线错、数字对不上、判据里有写操作、越界写入** → 打回重派,算第 4 步的一轮;**证据齐全、只差格式**(首行前多了旁白、一行塞了多处判据)→ 主会话自己修掉复跑,不打回、不算轮,progress 写一行。
- 复算不过,**汇报里就不许写 PASS**:除了验收官首行原话,还要补一句复算结果。

## 派单纪律(第 4 步用)

1. **一份任务书一个焦点**。要查六件就派六个,别塞进一份:焦点越多,agent 越倾向「再查一项」而不是「开始写结论」。
   - 代价写明:拆开是**数倍的 token**,墙钟靠并行基本持平。所以**整刀级验收才拆,单点改动照旧派一个**。
   - **一单 ≤5 个问题**,超了按模块拆成多单。
   - 拆开就得留一个汇总:跨维度的问题(A 的改动破坏 B)各看各的都可能漏。
2. **任务书末尾写死取证预算**:「最多 N 轮 / X 分钟,到点无条件停下写报告,没查完的项写『未验』」。
3. **不给开放授权**。「这趟要不要另跑一趟你自己定」这类把预算交回给 agent 的话一律不写。
4. **静默失败要自己认出来**:完成通知只有用量、没有结果 = 按静默失败处理,当场拆小、给预算重派。Agent 工具返回里带「stopped at its N-turn limit (partial result…)」就是撞了轮数上限。
5. **确实验不了的项预先授权免验**。有些项验收官每次都只能判「未验」(比如「交付范围越界」要用户字面列举的文件名单当尺子,可用户只说了要干成什么样;或者真机点页面要另起实例、被环境限制挡住)。真撞上了,就在任务书里对那一项写死:「本项已授权免验:<为什么这次验不了>。」**只授权你真的确认验不了的那一项**;授权了哪项,就得由派单人自己补上那项的核对。
6. **禁止按模式匹配杀进程、禁止碰共享状态**。多 agent 并行时工作区和进程表是共用的:要杀进程只许杀自己拿到的 PID;`git stash` / `git checkout -- ` / `git reset --hard` / `git clean` 一律禁用。

## 维护约束

细则一律写进乙节及以下,五步里只留一行指针。两条可数的线:**五步每步 ≤ 2 行**;**五步里最长的一步 ≤ 最短一步的 3 倍**(按字符数)。改完甲节当场量一遍。

# 丁、任务树

用户说「任务树」「出任务树」= 把当前项目 task_plan 的进度渲染成纯文字树。第 5 步「收」也出一棵,放在回复最末尾。

**机械实现** = `bash ~/.claude/skills/escort/scripts/task-tree.sh [--base <本会话基线>] [--out 任务树.md] [--全]`。**规则以本节为准,脚本只实现,不另立格式。** 不给 `--全` = 折叠版(头部 + 每个未完大活一行);收尾时给 `--全`(子项不许省)。

**什么时候出**:收尾时;用户说「任务树」时。**不是每完成一件就出**:一棵展开的树 60~100 行,写进对话后每轮都要重读。**一个会话一次。**

**展示规则**:
1. 树线用 `├─` `└─` `│`,缩进两格一层。
2. **只显示还没全部完成的大任务**;全完成的不显示。
3. 未完成的大任务列出它下面的**全部**子任务,已完成的也列,那是上下文。
4. 子任务还有子任务,继续往下展开。
5. 状态四态:`[✓]` 已完成 / `[→]` 进行中 / `[ ]` 未开始 / `[!]` 被阻塞。
6. **本会话完成的:状态符号后紧跟 `★`,行尾再写 `← 本会话`**;本会话新增的阻塞写 `[!]★ … ← 本会话新增`。
7. 每个大任务后写完成数 `(3/5)`、登记日期和挂了多少天;折叠版在行尾标 `⚠卡N`(底下有几个写着「阻塞:」的未完子项)。
8. 同一时间尽量只标一个 `[→]`。
9. 树末尾依次给:`━━━━━ 本会话完成 ━━━━━`、`本会话新增阻塞`、`当前正在处理`、`下一步`、`阻塞项`(没有就写「暂无」)。
10. 全部完成 → 只输出 `[✓] 所有任务已完成`。

**配色**:**颜色不单独承载含义**(有人分不清某些颜色)。`[✓]` 和 `★` 都是纯文字字符,要更醒目只许换形状或体积,不许换色相。

**数据从哪来**:大任务 = `task_plan.md` 里的 `- [ ]` / `- [x]`;挂了多少天 = 条目里的登记日期(`YYYY-MM-DD` 或 `MM-DD`)对今天;本会话完成 = `git diff <本会话基线>` 里同一行从 `[ ]` 翻成 `[x]`;阻塞 = 条目里写了「阻塞:」;等人 = 条目里标了〔等用户〕或〔等外部〕。**本会话基线**取摸底时记下的那个 HEAD;别把别的会话同时段的 commit 算成本会话的。

**做不到什么**:①没给 `--base` 就不标 ★,登记日期抓不到就不打日期,**不猜**;②大任务底下没有缩进的 `- [ ]` 子项,树只打一行「子任务盘上无结构」,一个字都不替它编;③本会话完成只认 checkbox 翻勾,纯内容追加数不出来。

# 戊、长跑

用户说「护航 长跑 <活>」「并驾 长跑 <活>」= 这个会话**到线不换窗口**:先收尾、再让 Claude Code 自动压缩、压完接着干,要拍板才停。甲、乙(并驾再加 `convoy.md`)照旧全吃,本节只写多出来的那一层。
口令顺序不讲究:「长跑 护航 …」「继续 长跑 护航」「护航长跑」、单敲「长跑」、缀在长句末尾的「开始吧 护航长跑」都算,机器也认;没带方式词的按护航跑。句子里只是在聊长跑(「长跑模式怎么用」「长跑 先不做」)不算。判法和漏在 `scripts/context-gate.js` 头注释。

## ① 机器侧(要先照 README「可选:长跑 hook」挂上;没挂就只剩 ② 的模型纪律)
- **认口令**:每条用户消息进来(UserPromptSubmit),`context-gate.js` 从头 3 个非空行认口令,认出就给本会话记长跑标记(`~/.claude/escort/long.txt`);会话中途敲也认。手动开关:`node ~/.claude/skills/escort/scripts/context-gate.js --long` / `--unlong`。
- **到线换话术**:长跑会话到线(默认占窗口 60%,`ESCORT_GATE_PCT` 改),Stop 拦下逼它先收尾,PreToolUse 往上下文注入同一段话;不补派单提醒(长跑本来就要一直派活);收尾之后再涨 10 万 token 才再催。
- **线下续跑**:长跑会话没到线、正要停、又没有在跑的 /goal → Stop 拦一次,叫它接下一格或弹窗问;被拦出来那一轮放行,所以每次想停只拦一回。开了 /goal 不拦。
- **PreCompact 守门**:没收过尾、或收尾之后又涨了 10 万 token 以上 → 挡掉这次自动压缩(挡了对话不压,接着跑);收尾新鲜 → 放行;占用超过窗口 90% 一律放行(超限的压缩被挡,那次请求会直接失败);手动 `/compact`、子 agent、非长跑会话一律放行。
- **压缩后**:SessionStart(compact)时闸把本会话的提醒计数和收尾标记归零,压完从头算;`post-compact-snapshot.sh` 把 git log、分支 + status、进度最新一条、任务树塞回上下文,长跑会话多一句「对照 task_plan 未完格接着干」。

普通(非长跑)会话也走这套 hook,但只是提醒:到线屏上打一句「该收尾了」、PreToolUse 往上下文补一句,不拦、不挡压缩。

## ② 模型纪律四条
1. 要用户拍板的事**一律 AskUserQuestion 弹窗**,不在正文问完就停,也不自己猜。
2. **每件小活收尾 = 写进度文件 + 提交自己的改动**:`git commit -- <路径>` 只提交自己改的路径。压缩随时会来,没提交、没写进进度文件的等于没做。
3. **到线照闸的话术收尾再继续**:到线前已开始的活先安全停下 → 收尾 → 跑 `node ~/.claude/skills/escort/scripts/context-gate.js --done` 记下收尾(自动压缩要看到这个才放行)→ 收完直接接下一格,不等用户。
4. **压完之后第一轮**:照 `compact-context` skill 的「压完之后第一轮」那节办,这里不另写一份。

## ③ 开窗
1. 权限切到不用每步审批的模式(比如 auto),不然半路卡在审批弹窗上没人点。
2. 敲 `/goal <条件>`,条件模板「<能从输出证明的收尾条件>;要拍板时用 AskUserQuestion 等用户;或跑满 N 轮即停」。不设也行,线下续跑会兜着;设了会话会一直跑到条件达成。
3. 第一句敲「护航 长跑 <活>」(批量活用「并驾 长跑 <活>」)。

## ④ 已知边界
- **挡后何时重试**:被挡的自动压缩在之后每次发请求前都会再试一次,没有冷却期。
- **/goal 压缩后还在**:自动压缩之后 goal 照样在评估,压缩摘要里也带着 goal 条件。
- **占用是估的**:最后一次响应之后刚回来的工具输出按字符折算,跟 Claude Code 自己的数差几千到两万 token。
- **放行后第一次不一定压**:紧跟工具输出回来那一刻的放行没压,下一轮再放行才压;原因没查到,对长跑无害。
- **压缩后快照要 cwd 在 git 仓里**:不在任何仓的,脚本静默退出,一个字不注入。
- **窗口靠猜**:没设 `ESCORT_CONTEXT_WINDOW` 时,100 万窗口的会话在用到 20 万之前按 20 万算,会提前催。
- **干等时不响**:主会话派完子 agent 之后自己干等、一个工具都不调,Stop 和 PreToolUse 都不响;PreCompact 只守门不催。
