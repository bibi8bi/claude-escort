# 并驾 · 降耗纪律

**这份文件不随 skill 自动加载。** 说「并驾 / 进阶并驾 / 全力」时整份读一遍,只说「护航」「任务树」不用读。
甲节(护航五步 + 必停点)、乙节(护航细则)、丁节(任务树)和那张口令表住 `SKILL.md`,两处打架以 `SKILL.md` 为准。

# 丙、并驾:第 3 步换成批量并行

用户说「并驾 <活>」= **按甲节五步闭环跑,只把第 3 步「干」换成批量并行**。五步细则、必停点、隐式默认记账、批量活标杆、汇报三条一律以甲、乙节为准。**拆不出值得独立承担的工作块 → 主会话自己干,不为用并驾而派。**

三个痛点写在最前面,免得跑偏:①**快**,能同时干的别排队;②**主对话不堆垃圾**,子 agent 的过程留在它自己那边,只把结论交回来;③**不许跑完才发现偏**。第 2 条是硬约束:**不写死返回格式,省下的上下文会原路吐回来**,并驾就白做了。

## 一、拆批(第 3 步开头)

先定队形:同类轻活走批队形(本小节),要经过多道岗位的活走流水线队形(第七小节);两种队形下样品闸与机械刹车都默认开。

**互不重叠是硬条件**:同一个文件只许一个 agent 动。两个 agent 改同一份文件,既冲突,又会被验收官判越界。

- 先给每个子任务列自己的 **Files 清单**,当场对一遍有没有撞车(把清单填进去整行跑):
  `printf '%s\n' <子任务1的文件…> <子任务2的文件…> | sort | uniq -d`,**输出必须为空**;有输出就是那几个文件被两个子任务同时认领了,回去重拆。
- **同时在飞最多 4 个**(上限,不设最低数),**回来一个、过了机械刹车(第八小节)就补派一个**,不等同批最慢的那个。
- **派单前先报总数**:「共 N 个子任务,同时最多 4 个」。
- **拆不动别硬拆**:后一步要吃前一步产出的(改完再测、生成完再汇总),老实串行,并说明哪几步是串的。
- 同一个模板要铺到 ≥3 个目标 → 那是乙节的「批量活标杆」:先立标杆定稿,再并行铺。

## 二、心跳基线(派单前必做)

心跳由 **hook 写,不由模型写**:模型会忘,agent 卡死了更不会写收工行。装置:`scripts/heartbeat.js` 挂在 `settings.json` 的 SubagentStart / SubagentStop 上(装法见 README);日志 `~/.claude/escort-heartbeat.log`,制表符五列 `ISO时间 / 事件 / 会话前12位 / agent类型 / agent_id`。

日志**跨会话累积**,所以要记两个东西。**派单前先跑这条**:

```
B=$(command grep -c '' ~/.claude/escort-heartbeat.log 2>/dev/null || echo 0); ME=$(printf '%.12s' "$CLAUDE_CODE_SESSION_ID"); echo "基线 B=$B  本会话=$ME"
```

- `B` 用 `command grep -c ''` 不用 `wc -l`:文件末尾没换行时 `wc -l` 少数 1 行。
- `ME` 取 `CLAUDE_CODE_SESSION_ID` 前 12 位,心跳日志第 3 列存的就是它。

**三道闸,缺一道就会算错数**:`B` 基线行数挡掉更早的旧事件;`ME` 会话过滤挡掉**别的会话正在跑的 agent**;`agent_id` 配对挡掉同会话但 Start 早于基线的半条记录。`ME` 取不到值时自动跳过会话过滤,只靠 `agent_id` 配对,不报错,但数会偏大。

## 三、进度行(每个 agent 回来立刻打,不许攒)

格式写死一行:`[进度 3/8] <子任务名> · PASS 或 FAIL · 动了 <k> 个文件 · 还在跑 <n> 个`

**「还在跑 n」不许自己数,必须来自心跳日志**。`B` 用第二小节记的那个:

```
tail -n +$((B+1)) ~/.claude/escort-heartbeat.log 2>/dev/null | awk -F'\t' -v now="$(date -u +%s)" -v me="$ME" 'me!=""&&$3!=me{next} {seen++} $2=="SubagentStart"{s++;t[$5]=$4;st[$5]=$1;last=$1} $2=="SubagentStop"{if($5 in t){delete t[$5];delete st[$5];d++;last=$1}else{o++}} END{if(seen+0==0){print "本次还没有心跳(一个 agent 都还没启停)";exit} k=0;for(x in t)k++; if(s+0==0){printf "启动=0 已回来=0 在跑=未知(基线后一条 SubagentStart 都没有,孤儿 Stop=%d;改按已回来的 agent 数报)\n",o+0;exit} c="date -u -d \""last"\" +%s"; c|getline ts; close(c); printf "启动=%d 已回来=%d 在跑=%d 本次最后事件=%d秒前\n",s+0,d+0,k,now-ts; if(o+0>0) printf "  (另有 %d 条孤儿 Stop:同会话但 Start 早于基线,已按 agent_id 配对忽略)\n",o+0; for(x in t){cc="date -u -d \""st[x]"\" +%s"; cc|getline as; close(cc); printf "  在跑: %s (%s) 已跑 %d 秒\n",t[x],x,now-as}}'
```

**⚠ 这条命令要从盘上文件里复制出来跑,别从对话里渲染出的那份复制**:带参数调起 skill 时,正文里的 `$1`~`$5` 可能被参数替换掉,而这条命令里它们全是 awk 字段变量,被替换了不报错、只会默默给出错的数。

**「在跑」只许来自 `agent_id` 配对,永远不许写成「启动数 − 完成数」**:日志跨会话累积,减法会算出负数。

**它自己会说明状态,照它说的做**:`启动=N 已回来=M 在跑=K` = 心跳正常,「还在跑」直接抄 K;`启动=0 … 在跑=未知` = 基线后一条 Start 都没有,**当场在回复里明说心跳没生效**,改按已回来的 agent 数报;`本次还没有心跳` = 第一批刚派出去还没动静,正常,若已经回来过 agent 还是这句 = hook 没装上。

**最该盯的是每个在跑 agent 的「已跑 N 秒」**,不是「本次最后事件」(后者会被别的会话刷新)。明显超出这类 agent 的常规寿命 → 当它已经死了,重派。

## 四、子 agent 返回格式(派单时原样写进任务书)

项目有术语表的,任务书**第一行**写:

```
开工前先读 <术语表路径>;专有叫法以表内定义为准,交付里不许自造同义词;任务书用词与表内定义冲突 → 停下回 FAIL 说明,不许猜。
```

末尾写死:

```
你只回四行,不多回:
1. 动了哪些文件(绝对路径,一行一个)
2. 一句话结论
3. PASS 或 FAIL(FAIL 要写一句原因)
4. 依据或卡点(≤2 句):凭哪条命令或哪行代码判的;没做完就写卡在哪一句话上
过程、思路、代码片段、复述任务书 —— 一律不回。
```

再加三句:每条验收命令或判据同行带「在验:<哪个目的>」(子 agent 拿不到目的,就只会照字面刷绿);只许动**你自己那份 Files 清单**里的文件;撞上必停点(删测试 / 真库真钱真发布 / 重启在用服务 / 要改方向 / 要写别的仓)→ **停下回 FAIL 说明**,不许自己拍板。

## 五、验收(第 4 步)

照甲节第 4 步派验收官,任务书五项写全。并驾特有两条:**Files 清单 = 所有批次的并集**,不是最后一批(只给最后一批,前几批的越界就查不出来);**体验师只在有 UI 产出时派**,没 UI 硬派它只能回 BLOCKED。

**补漏 agent**:活是**清查 / 调研 / 批量盘点**这类「要全」的,派验收官之前先派一个只读 agent,任务书只问一件事:「对照领单,还漏了什么:哪种查法没跑、哪句结论没核实、哪份该读的没读」。漏项主会话补做,补不了的写进汇报。改代码、写文档这类「要对」的活不派它,那归验收官管。

## 六、已知边界

1. `SubagentStart` 会发,各种 agent 类型都发。
2. 日志跨会话累积,别人的「孤儿 Stop」会混进来,靠三道闸挡。加了 `ME` 之后「孤儿 Stop」只剩一种含义:你自己的 agent 里有几个的 Start 早于基线。
3. **agent 被 API 错误杀掉时 `SubagentStop` 不发,心跳会一直显示它「在跑」**。心跳给不出「它是死是活」,只能给「它多久没动静」。
4. 心跳只记启停,记不了「干到哪」:「还在跑 3 个」是真的,「跑到 70%」给不出来,别编。
5. 主会话没有定时器,进度行是**事件驱动**的。轻量 agent 只活十几秒,轻量批次里几乎总是读到 `在跑=0`,那是正常的。
6. 心跳日志超 2MB 会砍到末 500 行,别拿它当长期审计账本。
7. 用 `SendMessage` 恢复一个 agent 会**再发一次 `SubagentStart`**,`agent_id` 不变。所以 `启动=N` 是启动事件数,不是派了几个 agent;进度行的分母要来自你自己的拆批清单。
8. `heartbeat.js` 任何异常都 exit 0(hook 非零退出会打断会话),所以「日志没长」只能靠第三小节的自检发现。
9. **撞 `maxTurns` 停下的子 agent 也不发 `SubagentStop`**,后果同第 3 条;要判是不是撞了上限,看 Agent 工具返回里有没有「stopped at its N-turn limit (partial result…)」。

## 七、队形与流水线

队形不写死,按当次任务切岗位、定队形。**批队形**:同类轻活拆 N 件,同时在飞最多 4 个,回来一个补一个。**流水线队形**:活要经多道岗位(例:调研 → 记录 → 审计)时**件与件不等齐**,哪件完成哪件先流向下一岗,下一岗忙不过来就再派一个同岗 agent。

两种队形同守:同时在飞 ≤ 4;Files 互不重叠;必停点照旧。流水线六条:
1. **重派上限 2 轮**:某件被判「交的 ≠ 领的」→ 换新 agent 重做;还不过 → 停下报用户。
2. **下游岗必须拿到上游的「领单」**:派记录岗时附上当初给调研岗的任务书原文,**对单收货**。
3. **分工写死**:记录 = 对单收货(答没答题、格式全不全);审计 = 验货(内容真不真、好不好)。**审计读上游原稿,不读记录岗的转述**:每转一道手丢一道真。
4. **登记文件分片**:两个记录岗不许写同一份文件;各写各的那片,主会话最后合并。
5. **主会话是事件驱动的**:「发现不一致立刻反馈」= 「主会话下次醒来时处理」,别按秒级刹车设计。
6. **第一件走全链条当样板**,走完再放量。

两个取舍:审计要横向对照才按组等齐,单件能判就按件走;**岗位别贪多**,每多一岗多一次转手损耗。

## 八、样品闸与机械刹车(并驾默认开)

治的病:**没人验「任务书是不是用户想的那件事」**,验收官和体验师验的都是「照任务书干对没有」。

**样品闸**(铺开前,与甲节必停点同权):
- 拆完批**先只派第 1 件**;流水线队形 = 第 1 件走完全链条。
- 完成后把**成品本身**(文件 / 截图 / 渲染结果)拿给用户过目,附一句「后面 N-1 件都长这样,继续?」。给的必须是成品,不是描述。
- 子任务不同类时,样品只代表它那一类,其余类补**一屏对稿单**:每条 ≤ 20 字大白话 + 一句「做完你会看到什么」,通篇不写文件名、函数名、参数名。
- 用户回「继续」→ 铺其余;用户派单时说「**免样品**」→ 本次跳过此闸。

**机械刹车**(每件回来时对三样,机械判,不凭感觉):①动的文件 ⊆ 该子任务的 Files 清单?②交付对得上「领单」和样品?③首行是不是 FAIL?任一中 → **刹车**:不派新单(在飞的等它们回来);该件换 agent 重做,**最多 2 轮**;2 轮不过 → 停下,给用户一行大白话「偏在哪」+ 报告原文。

## 九、全力模式

**只有用户说「全力 <活>」才开**。觉得某件活又大又难,可以推荐一句「建议开全力模式」,用户点头才开,**不许自己开**。全力 = 并驾全套照旧,再叠两条;多烧的 token 换的是少漏、少错。

1. **找到找不出新的为止**(只用在数量事先不知道的清查:找 bug、找漏网文件、找违规条目):一轮派几个只读 agent,各换一种查法;新找到的先跟**之前所有轮见过的**比(不只跟确认过的比,否则被驳掉的每轮都会冒回来),去重。**连续 2 轮没有新的才停**,最多 5 轮;到顶还在出新的 → 停下报还剩多少没收干净。
2. **要紧结论派人专门反驳**(只用在结论错了代价大的地方:动真库前的判断、对外交付、改权限):每条结论派 3 个只读 agent,各给一个角度(对不对 / 安全不安全 / 能不能复现),任务书写明「你的活是驳倒它,拿不准就判驳倒」。3 个里至少 2 个没驳倒才留。这一步不顶替验收官。

## 十、派单铁条:显式写 model

- 每次派子 agent **必须显式传 model**,哪怕就是主会话同款。内置类型默认继承主会话模型,主会话用的是最贵的模型时,它们也按最贵的跑。
- **唯一豁免:派验收官 / 体验师时不传 model**,让定义文件里写的那个生效。单次传的 model 优先级高于定义文件,派单时随手传个更贵的,就等于悄悄给验收官换了档。
- **别用 `CLAUDE_CODE_SUBAGENT_MODEL` 兜底**:它优先级最高,会把全部子 agent 压成同一个模型,与分层互斥。

## 十一、四层路由(模型 × effort × maxTurns 一起定档)

| 层 | 什么活 | 派给谁 | effort | maxTurns |
|---|---|---|---|---|
| L0 | 确定性机械活:数文件、精确 grep、格式核对、跑一条命令 | **不派 agent,主会话直接跑** | — | — |
| L1 | 低歧义只读:扫描归类、找文件、清点 | `L1轻活`(haiku,**有条件启用**,见下) | low | 20 |
| L2 | 有样板的实现:标杆定稿后的模板铺开、局部改动、文档改写 | `L2常规` / `L2通用`(sonnet) | medium | 40 |
| L3 | 高歧义 / 高风险(硬触发词见下)、难定的首件标杆、裁决(不含验收官 / 体验师) | `L3架构`(opus) | — | — |

- 派不派子 agent 和用哪个模型是两件事:先判拆不拆得出值得独立承担的工作块,拆得出才轮到本表定档。
- 定档不看任务名称,看五维:**判断难度 × 影响半径 × 错误好不好查 × 返工成本 × 最少要一起读多少东西才能判对**。
- **L3 硬触发词(命中任一直接 L3)**:跨模块 / 公共接口变更 / 未知依赖扩散 / 不可逆迁移 / 真库 / 改权限语义。**普通跨文件不算**(全推 L3 等于没分层)。只改一行但动了权限语义的,照样 L3。
- **L1 有条件启用**:haiku 窗口小,预估这件活峰值 token 不超过它窗口的四分之一、确实是低歧义只读活,才派 haiku;拿不准就派 sonnet。要动盘的活一律不走 L1。
- **不许为省钱硬塞小模型**:拆开会破坏判断(同一调用链 / 配置 / 规则必须一起读)就升档,并记一行原因。
- **低档失败升档必记原因码一行**:SCOPE_MISS / SEMANTIC_ERROR / FORMAT_ERROR / TOOL_LOOP / UNKNOWN_CONSTRAINT / CTX_MODEL_PROMOTE。不记就分不清是模型不行还是任务书不行;**连续同码 = 改路由表,不是改任务书**。
- `effort` 和 `maxTurns` 只能写在 agent 定义文件里,单次派单只能传 model。所以要吃到这两个数,派单时得**按 `subagent_type` 点名** `L1轻活` / `L2常规`。定义文件里的 `maxTurns` 到点会直接砍掉 agent,砍的那一刻它写不出报告,所以 agent 自己的预算要早于它停下。
- **这几份定义文件挡不住什么**:它们会出现在每个新会话的可选 agent 列表里,别的会话可能自己挑走。「不要自动挑选」只写在描述里,**是文字约束,不是机械闸**。风险不对称:L1 只读,挑错了顶多结论差;L2 会写盘,挑错了是真改动。

## 十二、两套预算,分开记

**容量预算**(防飘;分母 = 该 agent 实跑模型的上下文窗口,分子 = 峰值输入 + 输出):

| 线 | 值 | 动作 |
|---|---|---|
| 目标线 | ≤20% | 正常 |
| 收束线 | 20–30% | 不再扩调查范围 |
| **禁扩线** | 30–40% | 只收尾,不接新子任务 |
| **失控线** | ≥40% | 停 |

- 这四条线是运营护栏,不是校准过的质量临界线。
- **主会话同守**:到 20% 把状态写进 progress;到 30% 主动提议开新会话接力,不硬撑到 40%。
- **撞 40%:先写后停**。照下面模板填完再开新会话,写进当前项目的 `progress.md`,**新会话第一件事就是读它**:
  ```
  ## 接力交接(<日期> 会话 <旧会话ID> 撞失控线 <占比>% 移交)
  - 干到哪了:<已完成、已落盘的东西,给路径>
  - 下一步干啥:<新会话第一件事,具体到文件与动作>
  - 别踩的坑:<本会话试过不行的路子>
  - 基线:<各仓 commit SHA> / 未入库改动:<git status 的输出>
  ```
- **轮数线**(和容量线并列,先撞哪条守哪条):**跑到 30 轮开始写接力交接,不再接新子任务;40 轮无条件写完交接开新会话。** 容量线天然滞后;轮数线防的是「同一份上下文被重读几十遍」。「轮」= 不同 `message.id` 的 API 响应数,不是 jsonl 行数。
- **成本是另一套账**:不许拿容量占比代成本。峰值一样的两个 agent 成本能差百倍;真正的成本是「模型轮数 × 每轮重读的整个上下文」。

## 十三、轮数纪律:并发取证 + 不整读大文件

上下文的绝对体积不是问题,**重读次数才是**;重读次数 = 轮数。砍轮数只砍重读,输出是真在干活的钱,一格都不许砍。

1. **无依赖的工具调用同轮并发**(主会话与所有子 agent 都适用)。凡后一条**不需要前一条的输出**就能构造的,凑一批同轮发出。
   - **派单时把这段原样抄进任务书**(验收官 / 体验师的定义文件里已经有,不用抄):
     ```
     取证纪律:无依赖的工具调用同轮并发——凡后一条不需要前一条输出就能构造的(分别 grep/wc 各文件、
     对各仓分别 git status、几条互不相干的 exit 取证),凑一批在同一次回复里发出。
     有依赖的照旧串行,不许硬凑:前一条输出决定后一条查什么或查哪的,必须分开发,硬凑=假证据。
     并发不改内容:同样的命令、同样的 exit、同样的输出、同样的汇报格式,不许拿"要并发"当理由少查一项。
     ```
2. **大文件不整读、大输出不裸跑:先定位后取段,先收窄再跑**。超过 500 行的文件先 `grep -n` 拿行号,再带 `offset` / `limit` 取那一段;预计输出超过 100 行或 8K 字符的命令先加 `| head` / `wc -l` / `--porcelain` 收窄。
   - 代价写明:取段会漏掉段外内容。判据要引用、要数的行**必须真读到**,读不到就写「未验」。这是省钱纪律,不是降标纪律。

## 十四、验收官任务书:候选证据包

在甲节第 4 步那五项之上,再加三样:**基线 commit SHA、预检产物路径、已知风险**。

- 任务书写死一句:「以上均为待核证候选。先自行用 git diff 重建实际变更范围,与申报清单做双向差集,任何非空差集都要解释;范围外发现照报,不许因候选没列而跳过。」
- **三个预检产物,主会话派单前用 git 现造**(`<基线SHA>` 换成本次的;多仓各造一套):
  - `git -C <仓> -c core.quotepath=false diff --name-only <基线SHA> > <scratchpad>/actual_files.txt && git -C <仓> -c core.quotepath=false status --porcelain -uall | grep '^??' | cut -c4- >> <scratchpad>/actual_files.txt`(实得范围 = 已改 + 新增未跟踪)
    - **`-c core.quotepath=false` 不许省**:不加它,git 把非 ASCII 路径输出成八进制转义,和手写的中文文件名永远对不上,双向差集全是假阳。
  - 申报的 Files 清单(所有批次并集)一行一个,写进 `<scratchpad>/declared_files.txt`
  - `LC_ALL=C sort -u <scratchpad>/actual_files.txt > <scratchpad>/a.txt; LC_ALL=C sort -u <scratchpad>/declared_files.txt > <scratchpad>/d.txt; { echo '[实得有申报无]'; LC_ALL=C comm -23 <scratchpad>/a.txt <scratchpad>/d.txt; echo '[申报有实得无]'; LC_ALL=C comm -13 <scratchpad>/a.txt <scratchpad>/d.txt; } > <scratchpad>/scope_diff.txt`(差集非空,主会话先写一行解释再派单)
- 加一条**明显缺失检查**(有测试目录没测试文件、有入口没依赖之类),报告里给一行覆盖信心。

## 十五、终止协议与 EVIDENCE 行

**要落盘产物的重活**,返回格式在四行之后**加第 5 行** `EVIDENCE: <关键产物路径> exit=<N>`。轻活照旧四行。

每份子 agent 任务书末尾(接在四行返回格式之后)再加这段,一字不改:

```
以下板式只在你被外力停下(工具被拦 / 撞轮数上限 / 被要求收尾)时用,用了就不出四行格式;
正常完成一律走四行,两套不并用:
STATUS: STOPPED_CONTEXT 或 STOPPED_TURNS
DONE: 已完成范围
REMAINING: 未验证范围
EVIDENCE: 已产出证据路径
NEXT_SPLIT: 建议的下一会话任务单
```

**这套板式在「撞轮数上限」那一路用不上**:被那样停掉的 agent 一个字都来不及写,只能由派单人从外面判(Agent 工具返回里的「stopped at its N-turn limit」)。治本不在板式,在预算:让 agent 在撞上限之前自己停下写报告。
